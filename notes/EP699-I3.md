# Problem 699, the case i = 3: reduction and search

Claim checked by computer: there is no n <= 10^18 and no j with 3 < j < n/2 such that every prime
p >= 5 dividing C(n,3) fails to divide C(n,j). In particular #699 has no counterexample with i = 3,
j < n/2 and n <= 10^18. (The remaining case j = n/2 is covered by the n = 2j proof that the site lists
as accepted; that proof is relied on here, not re-verified.)

This is stronger than #699 needs for i = 3: the prime 3 is never used.

## Reduction

Fix n and j with 3 < j < n/2, and suppose no prime p >= 5 divides both C(n,3) and C(n,j).

Kummer: p does not divide C(n,j) exactly when every base-p digit of j is at most the same digit of n.
For p >= 5, p divides C(n,3) exactly when p divides n(n-1)(n-2). So for every prime p >= 5 dividing
n(n-1)(n-2), j is digit-dominated by n in base p.

Write n = s * a with s = 2^x 3^y the 6-smooth part of n. Let b and c be the parts of n-1 and n-2
coprime to 6.

1. If p^e exactly divides n (p >= 5), the lowest e digits of n are 0, so p^e divides j. Hence a | j.
   Put j = a * t. Then 1 <= t < s/2.
2. If p^e exactly divides n-1, the lowest e digits of n are 1, 0, ..., 0, so j mod p^e is 0 or 1.
   Since s * a = 1 (mod p^e), j = t / s (mod p^e), so t = 0 or t = s (mod p^e). Hence b | t(s-t).
3. If p^e exactly divides n-2, the lowest e digits of n are 2, 0, ..., 0 (p >= 5 > 2), so j mod p^e
   is 0, 1 or 2. Since s * a = 2 (mod p^e), j = 2t / s, so t = 0, s/2 or s (mod p^e).
   Hence c | t(s-t)(s-2t).

b and c are coprime and t(s-t)(s-2t) > 0 on 0 < t < s/2, with maximum 0.09623 s^3. So

    b * c <= 0.0963 * s^3.

Since b * c = (n-1)(n-2) / (6-smooth parts), n needs a 6-smooth part of size about n^(2/3) or more.

## Enumeration

Exactly one of n, n-1, n-2 is divisible by 3, and the powers of 2 sit in one of three ways (4 | n;
n = 2 mod 4; n odd). For each placement and each pair of exponents the smooth parts of n, n-1, n-2
are known, the bound caps n, and n runs over one arithmetic progression. For a limit of 10^15 this is
6344 progressions and 5,713,773 values of n.

For each n the program factors b and c (deterministic Miller-Rabin, Pollard rho), finds every t that
meets conditions 2 and 3 by CRT over the prime powers, and tests full digit-domination for every
prime >= 5 of n(n-1)(n-2).

## Controls

- `necessary_ref.py` lists, by brute force with no bound and no factoring, every (n, t) with
  b | t(s-t) and c | t(s-t)(s-2t). The enumerator's list is identical for n <= 300,000 (116 pairs)
  and n <= 3,000,000 (160 pairs). This tests the progressions, the bound and the residue search.
- `survivors_ref.py` tests digit-domination directly for every n <= 3,000,000 and finds no
  survivor, matching the enumerator.

## Limits

- Finite range only. Nothing here bounds n above 10^18.
- Only i = 3. The same idea for i = 4 needs a smooth part of about n^(1/3), which is far less sparse.
- The arithmetic is u64 with u128 products; the size bound is evaluated in floating point with the
  constant widened from 0.09623 to 0.0964 so rounding can only admit extra candidates.

## Extension to larger i (added 2026-11-18)

The reduction never used i = 3 beyond "the primes that matter are larger than 3". Let P be the set of
primes <= q and let i be any integer with 3 <= i < (next prime after q). Every prime outside P is
larger than i, so if it divides n(n-1)(n-2) it divides C(n,i) and is admissible for #699. Reading
"6-smooth" as "P-smooth" throughout, a counterexample (n, i, j) with j < n/2 again forces
a | j, b | t(s-t), c | t(s-t)(s-2t) and b * c <= 0.0963 s^3.

So one run with smooth set P rules out every i up to (next prime) - 1 at once:

| smooth set | covers i | limit | n examined | relaxed survivors | largest survivor n |
|---|---|---|---|---|---|
| {2,3} | 3, 4 | 10^18 | 67,644,548 | 0 | - |
| {2,3,5} | 3 to 6 | 10^15 | 53,042,038 | 5 | 4376 |
| {2,3,5} | 3 to 6 | 10^17 | 305,008,482 | 5 | 4376 |
| {2,3,5,7} | 3 to 10 | 10^12 | 18,298,750 | 64 | 4376 |
| {2,3,5,7} | 3 to 10 | 10^15 | 308,291,873 | 64 | 4376 |

**The survivor files are not counterexamples.** `results/verify-p2357-1e12-survivors.txt` (64 lines,
`n j`) and the `survive_primes_outside_set` lists in the `ep699-smooth*.json` files hold relaxed
survivors only. The {2,3} files are empty: with only 2 and 3 ignored nothing survives at all.

"Relaxed survivor" means (n, j) passes every prime outside P. With a larger P the test ignores more
primes, so small n start to pass it. All 64 have n <= 4376, and checking them against the real
statement with exact integers finds no counterexample: for each of the 64 pairs and each i from 3 to
min(j - 1, 10), gcd(C(n,i), C(n,j)) was computed and factored, 448 triples in all, and every one has a
prime factor >= i. The 5 survivors of the {2,3,5} run are among the 64.

Result: #699 has no counterexample with j < n/2 and
- i <= 4, n <= 10^18;
- i <= 6, n <= 10^17;
- i <= 10, n <= 10^15.

The 10^17 and 10^15 rows come from `ep699_i3` only (`results/ep699-smooth235-1e17.json`,
`results/ep699-smooth2357-1e15.json`); the second program was run to 10^15 and 10^12. Their survivor
lists are the same 5 and the same 64 pairs as at the lower limits (the 64 compared pair for pair against
`results/verify-p2357-1e12-survivors.txt`), so the exact check above covers them.

## Second implementation

`search/ep699_verify` was written from the specification alone, without reading `search/ep699_i3`.
It enumerates exact valuation patterns (no duplicates) and finds t by splitting the prime powers of
b and c into coprime factors instead of by CRT. Agreement:

- P = {2,3}, 10^18: 1174 pairs and 0 survivors in both programs.
- P = {2,3}, 10^15: the two lists of 820 pairs are identical line for line.
- P = {2,3,5,7}, 10^12: 14,758 pairs and the same 64 survivors in both.
- Its own brute-force checks: identical lists to n = 10^7 for three prime sets, to 10^8 for {2,3}.

Above those brute-force ranges, completeness rests on the argument plus the agreement of two
enumerations built differently, not on exhaustive comparison.
